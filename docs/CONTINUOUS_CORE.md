# Непрерывное описание потребительского профиля

Модуль дополняет прежние KMeans4 и Huber75: для каждого МО сохраняет пять координат годового профиля, четыре веса опорных профилей, восстановленный профиль и остаток восстановления. Обе прежние метки рассчитываются по сохранённым центрам и поправкам к расстоянию. Максимальный вес не заменяет прежнюю метку.

Это только применение сохранённой модели. Запуск не обучает модель, не меняет калибровку и не требует зарплат, отраслевых долей или будущих исходов. Поддерживаются расходы за 2023 и 2024 годы. Географический экономический кандидат из отдельного исследования не включён в эту модель и не принят как замена опорному решению.

## Запуск

Из корня репозитория в PowerShell укажите существующий CSV расходов и новый каталог результата:

```powershell
$panel = 'C:/data/expense-panel-2023-2024.csv'
$panelSha = (Get-FileHash -LiteralPath $panel -Algorithm SHA256).Hash.ToLowerInvariant()
python -m scripts.predict_continuous `
  --model models/continuous_atlas.json `
  --expected-model-sha256 6000163eb591530a6cb8135c6e3c3c0bd5e8f1ee17f7b2eaa92b38304b5bae38 `
  --panel $panel `
  --expected-panel-sha256 $panelSha `
  --year 2023 `
  --codec observed_full `
  --output outputs/continuous-2023
```

Хеш входа проверяет конкретные байты файла. Для воспроизводимого сравнения берите ожидаемый хеш из сохранённого описания набора данных; вычисление хеша непосредственно перед запуском само по себе не подтверждает происхождение файла. Ожидаемый хеш модели закреплён выше. Для 2024 года измените `--year` и каталог результата. Существующий каталог результата не перезаписывается.

Выбор опорных профилей задаётся явно: `legacy_centers` использует центры прежнего KMeans4, `observed_full` берёт сохранённые наблюдаемые профили полной выборки, `observed_core95` берёт сохранённые наблюдаемые профили центральной части выборки. Этот выбор меняет веса и остаток восстановления; пять исходных координат и обе прежние метки сохраняются.

CSV должен содержать `entity_id`, `territory_id`, `period`, `Здоровье`, `Маркетплейсы`, `Общественное питание`, `Продовольствие`, `Транспорт`, `Все категории`. Идентификатор имеет вид `tid_123`, соответствующий `territory_id` равен `123`. Даты записываются как начало месяца, например `2023-01-01`. Для каждого МО в выбранном году нужны все двенадцать месяцев без повторов. Расходы должны быть положительными конечными числами. Ошибки заголовков, числа полей, кавычек, идентификаторов и календаря приводят к отказу.

В Python доступны те же операции:

```python
from sbercluster.continuous_atlas import load_model, read_panel_csv, encode_panel

model = load_model('models/continuous_atlas.json', expected_sha256=model_sha)
panel = read_panel_csv('expense-panel.csv', expected_sha256=panel_sha)
result = encode_panel(panel, model, year=2023, codec='observed_full')
```

## Как читать результат

В новом каталоге появляются `atlas.csv` и `metadata.json`. Второй файл содержит параметры запуска и хеши входов, кода и итогового CSV.

| Поля CSV | Значение |
| --- | --- |
| `x0`–`x4` | Годовая медиана помесячных стандартизованных логарифмов отношения категорий расходов к общим расходам; калибровка фиксирована по 2023 году |
| `weight0`–`weight3` | Неотрицательные веса опорных профилей, сумма равна единице |
| `reconstructed0`–`reconstructed4` | Ближайшая точка в выпуклой оболочке опорных профилей |
| `residual0`–`residual4`, `residual_norm` | Разность исходной и восстановленной точки, её евклидова длина |
| `historical_kmeans4`, `sw_constrained_huber75` | Прежние метки по двум сохранённым правилам |
| Поля с окончанием `_boundary_radius` | Расстояние до ближайшей границы соответствующего правила назначения |
| `new_entity` | МО отсутствует в списке обучения сохранённой модели |
| `log_median_total` | Логарифм медианы общих расходов; отдельное описание уровня |
| `territory_transition_status` | `unresolved`: географическая непрерывность территории не подтверждена |

Веса служат геометрическими координатами; это не вероятности принадлежности, доли расходов или доли отраслей. При совпадающих или линейно зависимых опорных профилях одинаковое восстановление может иметь разные наборы весов. Остаток сохраняет информацию, которую четыре опорных профиля не передают; малый остаток не доказывает экономическую правильность описания.

Радиус границы выражен в единицах стандартизованного пространства. Возмущение с длиной строго меньше радиуса сохраняет соответствующую метку при фиксированной модели. На границе радиус равен нулю. Он не оценивает вероятность ошибки и не служит откалиброванной уверенностью. Статус нового МО также не подтверждает перенос качества модели на новые территории.

Модуль не устанавливает производственные типы, причинные связи или реальные переходы границ МО. Новое непрерывное описание и совместимость прежних меток проверяются отдельно от экономической полезности. Результаты экономического исследования сохраняют свои прежние ограничения; применения к расходам или исходам 2025 года здесь нет.

## Локальная проверка

```powershell
python -m unittest discover -s tests -p test_continuous_atlas.py -v
```

Проверки используют небольшие синтетические входы и сохранённую модель. Они сравнивают численную проекцию с независимым решением задачи с ограничениями, проверяют сохранение координат и меток, отказ на повреждённых данных и отсутствие перезаписи. Они не переобучают модель и не заменяют проверку на реальной панели или экономическую оценку.

Отдельная проверка на полной расходной панели сравнивает 8064 прежние метки для двух моделей и двух лет, а также проверяет сумму весов, восстановление координат и неизменность входных файлов:

```powershell
python -m scripts.verify_continuous_core `
  --panel data/processed/panel.csv `
  --expected-panel-sha256 a175b7646a528e900d61dd4ade8d84fb4549ffcbb977d845340107b4f3b3c0fa `
  --model models/continuous_atlas.json `
  --expected-model-sha256 6000163eb591530a6cb8135c6e3c3c0bd5e8f1ee17f7b2eaa92b38304b5bae38 `
  --output outputs/continuous-verification.json
```

Эта команда применяет готовую модель, запускает оба годовых прогноза и сохраняет подробный отчёт. Она требует исходную расходную панель с указанным хешем и отсутствующий файл результата. Проверка не читает будущие исходы и не оценивает экономическую полезность.
