# Техническое ядро: проверка 3 октября 2026

В совместной модели я исправил стоимость одиночного переноса: теперь она учитывает пересчёт обоих центров. Прежняя остановка при фиксированных центрах могла пропустить улучшение полной цели. Основной KMeans4 сохранён: повторное обучение дало буквальное совпадение всех 2 016 меток.

## Проверенные изменения

- Точные изменения SSE и дорожного разреза, обновление центров после каждого переноса; пустые группы запрещены. Локальная остановка, лимит проходов и возврат исходной модели при α=0 имеют разные статусы.
- Проверка официальных территориальных ID, календаря, размеров панели и manifest до вычислений. Дублированные ID, неверная форма меток и незавершённые запуски не принимаются за воспроизведение.
- Единое преобразование новых наблюдений сохраняет режим признаков и вес уровня расходов. Калибровка на подтверждающем периоде запрещена; старые параметры с нулевым весом уровня читаются совместимо.
- Численные проверки графов и разбиений; устойчивая нормировка DMoN и partial R². Чисто постоянный или полностью объяснённый исход остаётся неопределённым.
- Запись неуспеха и прерывания запусков; полная проверка настроек и свидетельств при повторном использовании. Экспорт проверяет каждое предусмотренное модельное сочетание и публикует окончательный каталог только после успешной сборки.

## Исправленная совместная модель

Одна панель 2 016×24, прежние признаки и дорожный граф, α=0,25, seed=1729, максимум 50 проходов. Для каждой из четырёх задач проверены два заранее заданных старта. Ни один старт не выбран по внешнему исходу.

## Внешняя проверка

Для дорожного K4 из исходного старта partial R²=0,030888, для исправленного регионального контроля — 0,038557. Разность −0,007669; парный 95% региональный bootstrap-интервал [−0,026421; 0,012619] включает ноль. Использованы 500 общих выборок и одна когорта из 2 004 МО. По отношению к KMeans4 разность −0,001479, интервал [−0,025777; 0,024609].

Улучшение собственной цели не подтверждает дополнительную экономическую пользу дорог. При продолжении из исторического конечного разбиения получается другой локальный результат; он также приведён полностью. Это разведочная проверка на уже изученном исходе, условная на фиксированные метки, а не новая отложенная оценка или причинный эффект.

## Приёмка и повторение

168 тестов прошли; компиляция всех модулей и скриптов прошла. Признаки всех 24 месяцев совпадают побайтно с исходной версией; максимальное изменение 18 прежних внешних R² — 3,33e-16. Все шесть сохранённых DMoN checkpoint при прямом вычислении сохранили метки и вероятности точно; изменение loss не превышает 8,94e-8. Обучение DMoN для этой проверки не повторялось.

```sh
python -m unittest discover -s tests -v
python -m compileall -q sbercluster scripts
python scripts/verify_joint_refinement.py --output artifacts/joint-refinement-repeated --bootstrap 500
```

Выходной каталог последней команды должен быть новым. Подготовка исходной панели описана в [инструкции](../../docs/REPRODUCE.md). Сохранённый набор содержит признаки, метки, конфигурацию и копии конкретных версий модулей. После вычисления изменена только проверка отсутствующих меток; математические формулы не менялись, исходный снимок сохранён.
