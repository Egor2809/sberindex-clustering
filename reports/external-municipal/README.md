# Внешняя проверка типов по открытой муниципальной статистике

Четыре опорных типа (`reports/experiments/2026-09-23-v2/validation/reference_assignments.csv`) описаны открытыми показателями Росстата почти по всем 2 016 МО. Метки фиксированы, кластеризация не пересчитывалась.

Получено 2026-10-01. Регистрация не нужна: архивы «Если быть точным» лежат в открытом Yandex Object Storage. Архивы большие (раздел 32 весит 1,3 ГБ), поэтому загрузчик читает из zip только нужный CSV через HTTP Range, проверяет SHA-256 распакованного файла (`member_sha256`) и сохраняет строки по фильтрам из `sources.json`: МО верхнего уровня, годовой период. SHA-256 сохранённых файлов тоже закреплён. Сайт Росстата использует сертификат Russian Trusted Sub CA. Если его нет в системном хранилище, передайте PEM-бандл через `--cafile` (сертификаты: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt и `russian_trusted_sub_ca_2024_pem.crt`). Целостность файла проверяется по SHA-256 в любом случае.

Что рассмотрено и не использовано:
- ИНИД (data.rcsi.science, датасет 115): БД ПМО только за 2006–2020 годы;
- интерфейс БД ПМО Росстата (`gks.ru/dbscripts/munst`): нет пакетной выгрузки;
- раздел 39 БД ПМО (отгрузка по видам деятельности): сильное засекречивание, не загружался.

## Сопоставление

- Ключ: восьмизначный ОКТМО МО, то есть код панели без дефисов и без хвоста `000` (`79-701-000-000` → `79701000`). У внутригородских МО Москвы и Санкт-Петербурга свои коды (`45 3xx 000`, `40 3xx 000`), и они сопоставляются так же.
- Росстат: строка листа с десятизначным ТЕРСОН-МО, первые 8 цифр которого равны ОКТМО, а цифры 6–8 равны `000`. БД ПМО: поле `oktmo` у МО верхнего уровня.
- Если по коду нашлось несколько разных значений, ставится статус `ambiguous` и значение не заполняется. Значения с пометкой источника «Аномальное значение показателя» исключаются (`flagged_anomalous`). Сопоставления по названиям нет.
- `population` берётся из бюллетеня Росстата на 1.01.2024, если там есть код 2023 года (1 756 МО). Иначе используется БД ПМО на 1.01.2023 (255 МО). Источник указан в `population_source`. Там, где есть оба значения (1 614 МО), медианное расхождение в логарифмах −0,009.
- Доли разделов = численность в разделе / общая численность. Если раздел отсутствует или скрыт в источнике, доля остаётся пустой, а не равна нулю. «Бюджетный сектор» = O+P+Q и заполняется, только если есть все три раздела.

Результат пишется в `municipal_indicators.csv` (по одной строке на МО, со статусами). Аудит лежит в `mapping_audit.json`.

## Сила связи: η² и тест Краскела-Уоллиса (`results.json`)

η² равна доле дисперсии показателя, которую объясняют четыре типа (население, зарплата и работники/1000 в логарифмах). «Регион» означает ту же долю после вычитания средних по субъекту, «Регион × тип МО» после вычитания средних по субъекту и типу МО. В скобках дан 95% интервал регионального бутстрепа (500 повторов).

| Показатель | Без контроля | Регион | Регион × тип МО | Без Москвы и СПб: без контроля / регион |
|---|---:|---:|---:|---:|
| Население | 0,453 [0,371; 0,533] | 0,432 [0,374; 0,486] | 0,338 | 0,475 / 0,457 |
| Зарплата | 0,463 [0,258; 0,605] | 0,130 [0,085; 0,183] | 0,083 | 0,289 / 0,157 |
| Старше трудосп. возраста | 0,262 | 0,146 | 0,120 | 0,299 / 0,152 |
| Торговля | 0,299 | 0,064 | 0,050 | 0,207 / 0,162 |
| Городская доля | 0,249 | 0,111 | 0,010 | 0,076 / 0,114 |
| Сельское хозяйство | 0,114 | 0,078 | 0,021 | 0,108 / 0,078 |
| O+P+Q | 0,110 | 0,070 | 0,038 | 0,066 / 0,082 |
| Работники/1000 | 0,062 | 0,022 | 0,010 | 0,110 / 0,055 |
| Обработка | 0,015 | 0,019 | 0,007 | 0,013 / 0,023 |

Тест Краскела-Уоллиса без контроля даёт p < 10⁻²⁴ для всех показателей, кроме обрабатывающей промышленности (p = 0,002). После контроля региона p < 10⁻⁵ для всех, кроме работников/1000 (p = 6·10⁻⁴) и обработки (p = 5·10⁻⁴). После контроля региона × типа МО незначимы городская доля, работники/1000, торговля, обработка и сельское хозяйство. Для отклонений от средних тест эвристический.

## Вывод

- Типы различаются прежде всего размером. «Городской сервисный» объединяет крупные МО: медиана 88 тыс. жителей, почти полностью городское население, самая высокая зарплата (99 тыс. руб.), больше всего торговли, меньше всего бюджетного сектора и сельского хозяйства.
- «Продуктовый: малые районы» объединяет малые сельские районы: 15 тыс. жителей, самая низкая зарплата (44 тыс.), самое старое население. Больше половины работников крупных и средних организаций заняты в госуправлении, образовании и здравоохранении, доля сельского хозяйства самая высокая. Даже внутри своего региона такие МО на треть меньше среднего и платят на 6% меньше.
- «Удалённый: мало маркетплейсов» объединяет малые (12 тыс.) МО с высокой «северной» зарплатой (84 тыс.), молодым населением и множеством рабочих мест на жителя (вахта, добыча). Внутри своего региона их зарплата обычная (−2%). Высокий уровень зарплаты объясняет география, а не тип.
- Размер МО отличает типы и внутри регионов: η² для населения почти не падает при контроле региона (0,45 → 0,43). Различия по зарплате, торговле и городской доле в основном межрегиональные: η² падает с 0,46 до 0,13, с 0,30 до 0,06 и с 0,25 до 0,11.
- Отраслевая структура типы почти не различает: доля обрабатывающей промышленности не зависит от типа (η² ≈ 0,02). Потребительский тип описывает размер и уклад МО, а не специализацию.

## Ограничения

- Зарплата и численность работников учитываются только по крупным и средним организациям, по месту регистрации организации, а не по месту жительства. Поэтому у центров Москвы и у вахтовых районов на 1000 жителей приходится больше 2 000 работников.
- Население взято из двух дат (1.01.2024 и 1.01.2023) по правилу выше.
- Отраслевые доли заполнены неравномерно, чаще у крупных МО.
- η² не скорректирован на число параметров. Бутстреп-интервалы описательные. Причинных выводов нет.
