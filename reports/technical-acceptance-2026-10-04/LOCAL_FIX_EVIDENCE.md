F01: the previous packet audit accepted all 12 resealed synthetic packets in each of four invalid cases: unsupported revision, missing mandatory coverage field, four-dimensional correction vector, and reversed interval. The existing canonical packet validator rejected each case. The runner now uses that validator with the public reference content hash, entity membership and region assignment. It checks packet structure, seals, coverage, dimensions, status and correction bounds. F02: the previous negative CLI control accepted a real missing Python module as an expected refusal. The positive route classified the same failure as exit 1. Expected refusals now require the declared final exception class, stable reason, exit 1 and the declared output absence or preservation policy. Dependency, import, invocation, launcher and timeout failures produce `SETUP_ERROR` / exit 2; unexpected contract failures produce `FAIL` / exit 1. Real subprocess fixtures cover these distinctions.
