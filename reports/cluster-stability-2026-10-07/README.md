# Устойчивость отдельных расходных групп

Расчёт использует сохранённые 30 месячных повторений 2023 года для 2016 МО. Опорой служит `historical_kmeans4`, исследовательскими альтернативами служат `sw_constrained_huber75` и `sw_constrained_ordinary`. Нового обучения нет.

| Группа опорного KMeans4 | МО | Средний Жаккар | Медиана | Диапазон | Частота совместного назначения исходных пар |
| --- | ---: | ---: | ---: | --- | ---: |
| Повседневные покупки и услуги | 644 | 0,846516 | 0,857314 | 0,681586–0,944277 | 84,12% |
| Преобладание повседневных расходов | 859 | 0,907507 | 0,916169 | 0,809989–0,963512 | 89,89% |
| Городской сервисный профиль | 386 | 0,954799 | 0,960050 | 0,881279–0,989744 | 99,04% |
| Низкая интенсивность маркетплейсов | 127 | 0,867213 | 0,876805 | 0,724409–0,961538 | 85,62% |

Наиболее чувствительна к выбору месяцев группа повседневных покупок и услуг; городской сервисный профиль в этом опыте сохраняет состав лучше других. Ни одна исходная опорная группа не получила Жаккар не выше 0,5. Хорошая устойчивость группы в среднем не гарантирует её для каждого МО: минимальная средняя доля сохранённых исходных соседей по группе у отдельных МО составляет соответственно 0,114; 0,175; 0,532; 0,331. Идентификаторы и числа каждого МО доступны в `entities.csv`.

Группы двух альтернатив имеют собственный состав. У H75 одна из них получила Жаккар не выше 0,5 в одном повторении; у ordinary такие случаи встречаются шесть раз в одной группе и два раза в другой. Их нельзя напрямую приписывать одноимённым опорным группам: названия выше относятся только к KMeans4. Более высокий общий ARI альтернативы сам по себе не гарантирует устойчивость всех её групп.

Для каждой исходной группы выбирается группа повторения с наибольшим коэффициентом Жаккара: размер пересечения, делённый на размер объединения. Сопоставление каждой группы независимо, поэтому две исходные группы могут получить одну и ту же наиболее похожую группу. Расщепление сохраняется как снижение сходства; несколько фрагментов не объединяются обратно. При равенстве сохранены все лучшие метки. Метод следует [Hennig, Cluster-wise assessment of cluster stability, 2007](https://www.homepages.ucl.ac.uk/~ucakche/papers/clusta.pdf), раздел 2; [документация fpc::clusterboot](https://github.com/cran/fpc/blob/master/man/clusterboot.Rd) даёт эталон такого подхода. Библиотека R здесь не используется.

`clusters.csv` показывает размер исходной группы, среднее и медиану Жаккара, весь наблюдённый диапазон и число повторений с Жаккаром не выше 0,5. Последнее число описывает сильное изменение состава в этой серии; это не порог принятия модели. Средняя частота совместного назначения считается по всем различным неупорядоченным парам внутри исходной группы и по всем 30 повторениям.

`entities.csv` показывает для каждого МО средний Жаккар множества остальных МО своей группы и долю сохранившихся исходных соседей по группе. Сам МО исключён. `pair-frequency-histograms.csv` сохраняет точное распределение количества совместных назначений от 0 до 30 для всех пар, отдельно по каждой паре исходных групп. Диагональ не учитывает пары МО с собой и не считает одну пару дважды. `draws.json` сохраняет лучшие сопоставления всех групп в каждом повторении. `summary.json` фиксирует источники, хеши и ограничения.

Повторения используют четыре циркулярных блока по три месяца, с возвращением, seed 2200–2229. Все модели получают одинаковую последовательность месяцев. На повторениях раньше переобучались центры; шкала расходов была фиксирована на 2023 год. Теперь читаются только метки. Порядок 2016 ID сверяется между `constrained/labels.json` и `constrained/provenance.json`; сохранённая модель должна точно воспроизвести исходные метки на сохранённых признаках. Хеш каждого прочитанного файла сверяется с архивным `manifest.json`. Метки NPY не содержат ID: их порядок подтверждён общей записью происхождения и сохранённым кодом `benchmark_frontier.py`, а не отдельным ID внутри каждого массива.

Для связи с названиями проверено точное равенство членства по ID между `historical_kmeans4` и опубликованным `joint_alpha0_k4`, затем точное сопоставление с `frozen_prototypes.json:reference_labels`. Названия прочитаны из `reports/review-2026-09-24/atlas_extension.json:profiles`. Сопоставление и SHA256 этих источников находятся в `summary.json`, поэтому совпадение номеров 0–3 не служит основанием для названий.

Это условная чувствительность к составу месяцев уже исследованного 2023 года. Диапазон и распределение 30 повторений не являются доверительным интервалом генеральной совокупности. Результат не доказывает правильное число групп, экономические типы, независимую устойчивость по территории или перенос на 2025 год. Значения исходов 2025 не читались. Соседство здесь означает совместное назначение в группу. Устойчивость порядка и состава 15 ближайших аналогов по расстоянию из этих меток не определяется: сохранённых признаков всех повторений нет.

Воспроизведение из корня проекта:

```console
.local\frontier-20261003\oracle-env\Scripts\python.exe -X utf8 scripts\report_cluster_stability.py
.local\frontier-20261003\oracle-env\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_cluster_stability.py -v
```

Вне локальной среды подставьте Python с зависимостями проекта. Скрипт читает [сохранённый архив](../model-frontier-2026-10-03/README.md), не обращается к сырым данным и записывает только в этот каталог. Тесты проверяют перестановку меток, расщепление, слияние, потерю соседей и отсутствие пар МО с собой.
